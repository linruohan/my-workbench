# 个人工作台设计文档

状态：草案  
日期：2026-11-01  
范围：单人使用、Windows 桌面、**所有业务数据仅保存在本机**

主体能力固定为六块：**任务、日程、知识库、Agent、提醒、通知**。产品体验要求 **极致性能与 UI 美观并存**——列表与切换必须瞬时，界面必须克制、清晰、可长时间盯着看；不为「好看」牺牲帧率，也不为「快」做成简陋工具感。

**数据本地保存是硬性要求，不是可选项。** 任务、日程、知识库、提醒、通知、Agent 会话与审批、插件与模型配置、API 凭据，全部落在本机目录；应用不设立云端账号，不把业务库上传到任何服务器。断网时六大能力（除「向外部模型发请求」外）完整可用。

任务管理对齐 [Super Productivity](https://github.com/super-productivity/super-productivity) 的任务模型与每日流程（今日、计划、时间表、项目与待办清单、标签、子任务、工时、重复、提醒）。Agent 与模型、插件对齐 [ZCode](https://zcode.z.ai/) 的宿主 / Agent 分工、Provider Registry、工具注册表与插件形态。不复制上述项目源码；不把 Jira / GitHub / CalDAV 同步纳入第一版。

## 1. 背景

日常工作被拆在三套工具里：笔记在思源或 Obsidian，今天做什么在任务应用，模型和工具在 Cherry Studio 或 ZCode 一类客户端。三套工具各自好用，但任务、笔记和对话不共享同一批对象。

本应用补的是这道缝：六大能力共用一个本地库与一套界面语言。任务采用 Super Productivity 的计划日 / 时刻 / 截止模型；日程覆盖按日计划与按时刻时间表；知识库用 Markdown 与双向链接；提醒由宿主调度；通知走应用内中心并在后台补系统通知；Agent 按 ZCode 方式与宿主高度集成，可管全部能力并接外部模型与插件。

## 1.1 主体能力

| 能力 | 用户感知 | 边界 |
| --- | --- | --- |
| **任务** | 收件箱项目、今日、项目列表 / 待办清单、标签、子任务、计时、重复 | 不负责长文知识；短笔记挂在任务上 |
| **日程** | 计划（按日）、时间表（按时刻）、本地日程块、今日右侧时间线 | 外部 CalDAV 同步第一版不做；与任务共享计划字段 |
| **知识库** | 笔记树、Markdown、双向链接、全文检索 | 不做白板与多维表；正文可导出 |
| **Agent** | 会话、工具面、审批、外部模型、本地插件 | 不直连数据库；密钥在宿主 |
| **提醒** | 计划提醒、截止提醒、相对偏移 | 调度在宿主，不依赖 Agent 进程 |
| **通知** | 应用内通知中心、到期弹层、托盘 / 系统通知 | 提醒是来源之一；Agent 与系统消息也可入列 |

六块能力在导航上并列可见，数据上交叉引用（任务有提醒，提醒产出通知，Agent 可改任务与笔记，日程视图读同一批任务）。

## 2. 目标

1. 六大主体能力都能在应用内独立完成主路径，且互相打通，不依赖外部专用 App 才能「做完一天」。
2. 打开应用后落在「今日」，同时看到今天的任务与日程时间块；冷启动与视图切换以「感觉瞬时」为验收标准（见第 5.1、9.3 节指标）。
3. 捕获不离开键盘。未写日期的任务进入收件箱项目，不自动占据今天。
4. 计划日、具体时刻、截止日三者分开存。改其中一项时，任务列表、日程计划、时间表一起变。
5. 定时提醒到期后先走应用内通知；应用在后台时再补系统通知。
6. 知识库可写、可链、可搜；与任务、Agent 共用项目上下文。
7. Agent 经统一工具面管理六大能力；可接入外部模型；可用插件扩展。
8. **所有数据本地保存。** 业务库、会话、通知、配置、凭据均在本机；复制应用数据目录即可完整备份与迁移。
9. 断网时任务、日程、知识库、提醒调度、通知中心、历史 Agent 会话均可用。仅「调用外部（非本机）模型」需要网络。
10. **性能与美观并存**：交互延迟、滚动与动画有硬指标；视觉有统一设计语言，但不引入拖慢主线程的装饰。

## 2.1 本地数据边界

| 类别 | 存放位置 | 是否出本机 |
| --- | --- | --- |
| 任务、项目、标签、计时、重复 | `workbench.db` | 否 |
| 日程块 | `workbench.db` | 否 |
| 知识库笔记与链接、FTS 索引 | `workbench.db` | 否 |
| 提醒字段与通知中心记录 | `workbench.db` | 否 |
| Agent 会话、消息、审批 | `workbench.db` | 否（发给外部模型的是当次请求内容，见下） |
| Provider 列表、默认模型、权限、提醒默认偏移 | `config.json` | 否 |
| API Key / OAuth 令牌 | 系统凭据库或本地 `credentials` 文件 | 否；仅在用户发起的模型请求里作为请求头使用 |
| 插件目录 | `plugins/<id>/` | 否；仅本地安装 |
| 嵌入向量（第 4 阶段） | 本机 `chunks` 表或旁路文件 | 否 |

唯一允许离开本机的流量：

1. 用户主动调用**外部**模型时，Host 按当次会话组装的提示词、工具结果摘要等请求体；
2. 用户启用的 MCP 插件若指向外部服务，仅该插件声明的调用。

以上都不构成「业务数据云同步」。本机 Ollama 等本地模型不经过公网。应用**不得**静默上传库文件、使用统计中的笔记正文、或未确认的会话全文。

## 3. 非目标

第一版以及紧随的几个阶段明确不做：

- 云端账号、云端主副本、强制登录
- 把 `workbench.db` 或笔记同步到厂商服务器
- 多人实时协作、权限、评论
- 无限白板、自研块编辑器、多维表格
- 手机端
- 绑定单一模型厂商；不自建模型
- Super Productivity 的 Jira、GitHub、GitLab、CalDAV 同步
- 用标签或状态位手工维护「今日」成员
- 官方插件市场与远程签名分发（先支持本地目录安装与启停）
- 浏览器接管、电脑操控类高风险工具（ZCode 的 Browser Use / Computer Use 不进第一版）

可选的第二台设备同步（第 5 阶段）只能是**用户自管**的本机到本机方式（例如用户复制库文件、自建网盘文件夹、日后自托管同步），同步后每一台设备上的文件仍是完整本地副本，应用永不依赖「云上那一份才是真的」。Agent 对写操作默认需要确认；会话可切换到「信任本会话自动批准」模式，但删除与清空类操作始终二次确认。

## 4. 使用者与场景

使用者是一个人，主要在 Windows 上处理自己的任务和笔记，并会调用大模型整理、改期、起草。

| 场景 | 入口 | 结果 |
| --- | --- | --- |
| 早晨开工 | 打开应用，落在「今日」 | 从项目或待办清单里挑 3 到 5 件拖到今天，给每件一个预计时长 |
| 随手捕获 | `Ctrl+K` 或 `N` | 无日期时进入内置收件箱项目；写了「今天」才进入今日 |
| 排到某一天 | 计划视图 | 只写计划日，不写时刻。该任务出现在对应日期的列里 |
| 排到某一时刻 | 时间表 | 写入具体时刻后，任务离开计划视图的日期列，画在时间线上 |
| 设提醒 | 任务详情或排期时 | 选择「到点提醒 / 提前 5·10·15·30 分钟 / 1 小时」；到点弹出应用内通知 |
| 记住截止 | 任务详情里的截止日 | 时间表上出现截止标记；可单独设截止提醒 |
| 推进一件事 | 任务详情 | 从这件任务启动计时；停下来时留一句任务笔记 |
| 拆开一件事 | 任务详情 | 建成子任务。父任务的已用工时由子任务汇总 |
| 记录知识 | 笔记 | Markdown 正文，用链接指向别的笔记或任务 |
| 用 Agent 管工作台 | Agent 面板或 `/` 命令 | 自然语言创建任务、改计划、设提醒、写笔记、开计时；写操作按权限模式确认 |
| 换外部模型 | 设置 · 模型 | 在 Provider Registry 里加 OpenAI 兼容 / Anthropic Messages / 本机 Ollama，密钥留在宿主 |
| 装插件 | 设置 · 插件 | 从本地目录启用插件；技能、斜杠命令、子 Agent、MCP 一并注册 |

## 5. 设计原则

### 5.0 性能与美观并存（产品级约束）

1. **先保证主路径帧率，再谈装饰。** 今日列表、计划列、时间表滚动、命令面板打开必须稳定流畅；毛玻璃、大阴影、全屏模糊若测出掉帧则降级或关掉。
2. **美是秩序，不是堆料。** 一种强调色、两级字重、固定间距尺度；留白服务于扫读，不做大卡片墙。
3. **瞬时反馈。** 点击、拖放、完成打勾在 100ms 内有视觉响应；落库可异步，但 UI 乐观更新后与 SQLite 对齐。
4. **重活离开 UI 线程。** FTS 重建、嵌入、模型流式、MCP 与提醒扫描在 Host / Worker；Renderer 只收增量。
5. **动画有目的且可关。** 面板滑入、列表重排用短位移（≤180ms）；系统「减少动态效果」开启时全部切瞬时切换。
6. **暗色与亮色同等质量。** 对比度达标；强调色在两种主题下都不过曝。

### 5.1 领域原则

1. **今日由计划日计算。** 成员来自 `due_day` 或 `due_with_time`，不来自标签，也不来自单独的状态字段。排序可以单独保存，成员以日期为准。
2. **计划日和截止日是两件事。** 计划日表示打算哪天做，截止日表示最晚何时完成。只有计划日把任务送进今日、计划视图和时间表。
3. **有时刻的任务归时间表。** `due_with_time` 与 `due_day` 互斥。写了具体时刻就清空计划日；读取时时刻优先。计划视图只显示没有具体时刻的任务。
4. **提醒挂在任务 / 日程上，由宿主调度。** 到期推送到通知中心，不依赖 Agent 进程是否在跑。
5. **项目是任务与笔记的归属容器。** 每条任务必有项目。未归类的落在不可删除的收件箱项目。项目内再分「进行列表」和「待办清单」。
6. **计时记在任务上。** 按本地日期累加毫秒。
7. **所有数据只写本机。** 权威数据在本地 SQLite 与应用数据目录；没有云端真相源。界面不因为没有网络而等待。
8. **宿主持有真相与凭据，Agent 经工具面操作。** 模型密钥、数据库、提醒调度在宿主；Agent 不私藏密钥，也不绕过领域层写库。
9. **Agent 工具面覆盖六大主体能力。** 界面能做的事，工具契约里都有对应工具；读操作可自动，写操作按权限模式确认。
10. **插件是可启停的能力包。** 技能、命令、子 Agent、钩子、MCP 打成一个目录；启用注册、停用卸载；插件文件同样只存本机。
11. **每一阶段都能单独使用。** 后一阶段往同一个库上加能力，不新开数据源。

今日的收录规则：未完成，且计划日（有时刻时取该时刻的本地日期）早于或等于今天。父任务已在今日时，其子任务嵌在父任务下面，不在列表里再占一行。截止日不参与这条判断。

## 6. 信息架构

侧栏按六大主体能力组织；任务与日程的细入口沿用 Super Productivity 的工作方式。

```
工作台
├── 今日              首页：任务 × 日程时间线
├── 任务
│   ├── 项目          收件箱 + 自建项目（进行列表 / 待办清单）
│   └── 标签          横切筛选，无「今日」标签
├── 日程
│   ├── 计划          按日排列、无具体时刻
│   └── 时间表        按时刻 + 本地日程块 + 截止标记
├── 知识库            笔记树、链接、搜索
├── Agent             会话、审批、斜杠命令
├── 通知              提醒与其它消息的应用内中心
└── （顶栏）提醒入口    未读数；详情在通知中心
```

命令面板（`Ctrl+K`）跨六大能力检索，不占常驻侧栏项。

今日页面分两栏：

- 左栏：今日任务，按保存的顺序排列，可按项目分组。当前正在计时的任务钉在顶部。有子任务的父任务可展开。有提醒的任务显示小铃铛。
- 右栏：今天的时间表。有 `due_with_time` 的任务按时刻和预计时长画成时间块；只有计划日、没有时刻的今日任务列在时间线旁边，不占具体时段。

计划视图向后展示约 15 个日期列（可按工作日设置跳过周末）。每一列是该日 `due_day` 等于该日的未完成父任务，以及重复规则投影出来、尚未落成实例的条目。列头显示这一天的预计时长合计。

时间表默认看今天，可翻到之后约 30 天。固定时刻的任务和本地日程占时间块。截止日画成标记，不把计划日和截止日之间的空档画成占用。

Agent 面板可从侧栏打开，也可从任务 / 笔记详情滑出；始终能看见当前对象。通知中心从顶栏铃铛进入，不永久占第三栏。

```
┌──────────┬────────────────────────────┬─────────────────┐
│ 侧栏 220 │ 主区域                      │ 今日时间表 320   │
│          │                            │ 或详情 / Agent   │
└──────────┴────────────────────────────┴─────────────────┘
```

设置、备份、模型 Provider、插件、工作日开始与结束时间、默认提醒偏移从命令面板打开。

## 7. 交互

日常循环沿用 Super Productivity 手册里的短流程：挑出今天的几件结果，拖进今日，写上预计时长，从任务本身开始计时，停下来时留一句笔记。

### 7.1 命令面板

`Ctrl+K` 打开。输入同时搜标题和命令。列表顺序：

1. 用当前输入新建任务、笔记
2. 匹配到的任务、笔记、项目、标签
3. 与当前页面相关的命令（在今日时，「排到今天」「排到某时刻」「设提醒」靠前）
4. 已启用插件注册的斜杠命令（以 `/` 开头时优先）

方向键移动，回车执行，`Esc` 关闭。

### 7.2 快速输入

在今日和项目里按 `N` 聚焦快速输入。一句话里识别：

| 片段 | 写入 | 例子 |
| --- | --- | --- |
| 今天、明天、下周X、M月D日 | `due_day`，并清空 `due_with_time` | `明天写周报` |
| 上午、下午、HH:mm | `due_with_time`，并清空 `due_day` | `下午3点评审` |
| `提醒…` / `提前N分钟` | `remind_at` 或相对偏移 | `下午3点评审 提前15分钟` |
| `截止…` | `deadline_day` 或 `deadline_with_time` | `截止周五交稿` |
| `#项目名` | `project_id`；没有这个项目则不自动创建，项目名留在标题里 | `#工作台 定数据表` |
| 无日期 | 收件箱项目，两个计划字段都空 | `回复邮件` |

识别结果在提交前显示成一行摘要。时刻和计划日不会同时留下。仅有计划日、没有具体时刻时，默认提醒可设为当天工作日开始时间，或「不提醒」——具体默认值在设置里。

### 7.3 拖放

| 动作 | 结果 |
| --- | --- |
| 拖到今日 | 设 `due_day` 为今天，清空 `due_with_time` |
| 拖到计划视图的某一天 | 设 `due_day` 为那一天，清空 `due_with_time` |
| 拖到时间表的某一时刻 | 设 `due_with_time`，清空 `due_day`。块的时长取 `time_estimate`，空则按 30 分钟。按设置写入默认 `remind_at` |
| 拖回项目的待办清单 | 清空计划日、时刻与提醒，任务进入该项目的待办清单 |

### 7.4 列表快捷键

| 键 | 作用 |
| --- | --- |
| `N` | 新建 |
| `T` | 计划日设为今天，并清空具体时刻 |
| `R` | 打开提醒选项 |
| `B` | 移入当前项目的待办清单，并清空计划与提醒 |
| `Enter` | 打开详情 |
| `Space` | 完成 / 恢复 |
| `?` | 快捷键表 |

鼠标可以完成同样的操作。

### 7.5 完成与重复

完成时写 `done_on`，并清除未触发的提醒。重复不是任务上的一个枚举，而是独立的重复配置，任务用 `repeat_cfg_id` 指向它。只有没有父任务的主任务可以重复；子任务没有「重复」一行。

第一版配置支持：

| 项 | 取值 |
| --- | --- |
| 周期 | 每天、每个工作日、每周的某几天、每月的某一天 |
| 节奏 | `fixed`：锚在起始日；`after_completion`：从完成时刻起再隔一个周期 |
| 逾期 | `keep_latest`：只保留最新一份未动手的实例；`keep_all`：过期实例都留下。每天重复默认 `keep_latest` |
| 新实例默认值 | 预计时长、任务笔记、标签、可选的时刻与提醒偏移 |
| 子任务 | 可选：从上一份实例复制子任务 |

固定节奏在打开应用或打开该项目时补齐到期实例。完成后间隔要等这次完成才生成下一次。已经记过工时或改过标题的实例，在 `keep_latest` 下也不删除。

### 7.6 计时

当前只有一个计时任务。开始计时时若已有另一个在走，先把那段时间结算到原任务。结算写入 `time_spent_on_day` 里「本地日期 → 毫秒」的一格，`time_spent` 是各日之和。应用退出时结算到退出时刻。

有子任务的父任务不单独计时，它的工时和预计时长由子任务汇总后显示。

### 7.7 提醒与应用内通知

提醒选项对齐 Super Productivity 的常用偏移：

| 选项 | 计算 |
| --- | --- |
| 不提醒 | `remind_at` / `deadline_remind_at` 为空 |
| 到点提醒 | 等于 `due_with_time` 或截止时刻 |
| 提前 5 / 10 / 15 / 30 分钟 | 计划或截止时刻减去对应毫秒 |
| 提前 1 小时 | 同上 |

规则：

1. **计划提醒**优先挂在 `due_with_time` 上。只有计划日、没有时刻时，若用户显式要提醒，则把提醒时刻落在该日的「工作日开始时间」（设置项），不伪造一个 `due_with_time`。
2. **截止提醒**独立存 `deadline_remind_at`，与计划提醒可同时存在。同一任务两者同时到期时，应用内通知合并为一条，标题标明「计划 / 截止」。
3. 改期时按原偏移重算提醒；清空计划或移入待办清单时清空对应提醒。
4. 到期后由**宿主提醒调度器**投递，不依赖 Agent 子进程。
5. **应用内通知**是主通道：顶栏铃铛、通知中心列表、到期时的应用内弹层（可稍后提醒、完成、打开任务、忽略）。忽略只抑制该次出现约 5 分钟，提醒本身仍有效，避免过期提醒每秒抢焦点。
6. 应用在后台或最小化时，额外发一条 **Windows 系统通知**；点击聚焦窗口并打开该任务。第一版不做「应用完全退出后的系统级后台常驻服务」；托盘驻留开启时调度器继续跑。
7. Agent 可通过工具创建、修改、关闭提醒；写操作仍走权限确认。

## 8. 领域模型

库文件名 `workbench.db`，仅存在于本机应用数据目录（或用户指定的本地路径）。任务、项目、标签按 Super Productivity 的不变量拆开存；笔记仍是单独的对象；Agent 会话另表。实现时用迁移脚本建表。排序用顺序表，不用大段 id 数组，但读取规则与 Super Productivity 一致。应用不包含任何「上传数据库」的后台任务。

### 8.1 projects

| 列 | 说明 |
| --- | --- |
| id | 文本主键。收件箱固定为 `inbox` |
| title | 标题 |
| is_archived | 归档后从侧栏隐藏，任务仍在 |
| is_done / done_on | 完成项目。不连带改写任务的工时 |
| created_at / updated_at | Unix 毫秒 |

`project_tasks`：`project_id`、`task_id`、`bucket`（`active` 或 `backlog`）、`position`。一条任务只出现在一个项目的一个桶里。移到待办清单时清空 `due_day`、`due_with_time` 与计划提醒。

### 8.2 tasks

| 列 | 说明 |
| --- | --- |
| id | ULID |
| project_id | 必填，默认 `inbox` |
| parent_id | 子任务指向父任务，否则为空 |
| title | 标题 |
| notes | 任务自己的短笔记，Markdown。知识库长文不放这里 |
| is_done | 是否完成 |
| done_on | 完成时刻，可空 |
| due_day | `YYYY-MM-DD`，全天计划。与 `due_with_time` 互斥 |
| due_with_time | Unix 毫秒，具体时刻。与 `due_day` 互斥 |
| deadline_day | `YYYY-MM-DD`。与 `deadline_with_time` 互斥 |
| deadline_with_time | Unix 毫秒。与 `deadline_day` 互斥 |
| remind_at | 计划提醒时刻，可空 |
| deadline_remind_at | 截止提醒时刻，可空 |
| time_estimate | 预计毫秒，默认 0 |
| time_spent | 各日之和，由 `time_spent_on_day` 算出 |
| time_spent_on_day | JSON 对象，键为本地日期 |
| repeat_cfg_id | 可空。子任务必须为空 |
| created_at / updated_at | Unix 毫秒 |

写入计划时的不变量，放在领域层，不靠界面记得去清空：

- 设置 `due_with_time` 时把 `due_day` 置空；设置 `due_day` 时把 `due_with_time` 置空。
- 读取时若两列意外同时有值，以 `due_with_time` 为准。
- 截止日的两列遵守同一套规则。
- 子任务不能写入 `repeat_cfg_id`。
- 完成任务时清空 `remind_at` 与 `deadline_remind_at`。

`today_order` 只存 `task_id` 和 `position`。它不决定谁属于今日。读今日时：先按第 5 节的日期规则得到成员，去掉「父任务也在今日」的子任务，再按 `today_order` 排列，最后把新出现的任务按计划时刻接到末尾。顺序里已经失效的 id 直接忽略。

### 8.3 tags

| 列 | 说明 |
| --- | --- |
| id | 文本主键 |
| title | 标签名 |
| color | 可选 |

`task_tags`：`task_id`、`tag_id`、`position`。禁止存在 id 为 `TODAY` 的标签，也禁止把「今日」写进 `task_tags`。标签列表同样隐藏「父任务已带该标签」的子任务，避免同一件事出现两次。

### 8.4 repeat_configs

| 列 | 说明 |
| --- | --- |
| id | 文本主键 |
| title | 新实例默认标题 |
| project_id | 新实例所属项目 |
| cycle | `day` · `week` · `month` |
| interval | 每几次，第一版界面只用 1 |
| weekdays | 周重复时的星期，JSON 数组 |
| month_day | 月重复时的日 |
| schedule_type | `fixed` · `after_completion` |
| start_date | 节奏起点 |
| start_time | 可空，`HH:mm`。有值时实例写 `due_with_time` |
| default_remind_offset_ms | 可空。相对计划时刻的提醒偏移 |
| overdue_policy | `keep_latest` · `keep_all` |
| default_estimate | 毫秒 |
| default_notes | 文本 |
| inherit_subtasks | 是否复制上一份的子任务 |
| tag_ids | JSON 数组 |

### 8.5 日程块

本地日程用 `events`：`id`、`title`、`start_at`、`end_at`、`remind_at`、`notes`。它不是任务，没有项目，也不进入今日任务列表。时间表同时画任务时间块和日程块。外部日历同步不在第一版。

### 8.6 笔记与链接

`notes`：`id`、`project_id`（可空）、`title`、`body_md`、`created_at`、`updated_at`。

`links`：`from_id`、`to_id`、`rel`。`rel` 第一版只有 `mention`，用于笔记与笔记、笔记与任务之间的引用。任务之间的前后关系用子任务表达，不另造一种阻塞关系。

### 8.7 通知投递

`notifications` 存应用内通知中心的记录，提醒调度器写入：

| 列 | 说明 |
| --- | --- |
| id | ULID |
| kind | `task_remind` · `deadline_remind` · `event_remind` · `agent` · `system` |
| title / body | 展示文案 |
| ref_type / ref_id | 关联任务、日程或会话 |
| fire_at | 计划触发时刻 |
| status | `pending` · `delivered` · `snoozed` · `dismissed` · `acted` |
| snooze_until | 可空 |
| created_at / updated_at | Unix 毫秒 |

调度器每分钟扫描一次到期项（应用活跃时可用更短的定时器）；投递后更新 status，并推前端。忽略产生的 UI 冷却只放在内存，不落库。

### 8.8 Agent 会话

| 表 | 列 |
| --- | --- |
| agent_threads | id、project_id（可空表示全局）、title、model_ref、permission_mode、created_at、updated_at |
| agent_messages | id、thread_id、role（`user` · `assistant` · `tool` · `system`）、content、tool_name、tool_call_id、created_at |
| agent_approvals | id、thread_id、tool_name、args_json、status（`pending` · `approved` · `denied`）、created_at、resolved_at |

写工具默认生成 `agent_approvals` 待确认项；只读工具不进审批。`permission_mode`：`confirm`（默认）、`session_auto`（本会话自动批准非破坏性写）、`readonly`（禁止一切写工具）。删除任务、删除笔记、清空提醒、归档项目始终要求显式确认，即使处于 `session_auto`。

### 8.9 插件与模型配置

插件与 Provider 配置不进 `workbench.db` 业务主库，而放在应用数据目录：

```
workbench/
├── workbench.db
├── config.json          # Provider Registry、默认模型、权限默认值、提醒默认偏移
├── credentials.bin      # 或系统凭据库；Agent 不直接读
└── plugins/
    └── <plugin-id>/
        ├── .workbench-plugin/plugin.json
        ├── commands/
        ├── skills/
        ├── agents/
        ├── hooks/hooks.json
        └── .mcp.json
```

插件清单字段：`name`、`version`、`description`、可选 `mcpServers`、可选 `ui`。启用状态记在 `config.json`。停用时卸载其命令、技能、子 Agent、钩子与 MCP。

### 8.10 检索

任务标题、任务笔记、笔记正文建 FTS5 虚表，分词用 SQLite 自带的 `trigram`。命令面板先查标题，列表不超过 20 条。

嵌入向量不进第一版。第 4 阶段另加 `chunks`。删笔记时一并删掉它的片段。

## 9. 系统架构

对齐 ZCode 的三层分工，用 Tauri 落地：界面、宿主服务、Agent 运行时分开；密钥与数据库在宿主，Agent 经协议调工具。

```
┌──────────────────────────────────────────────────────────┐
│ React 界面（Renderer）                                    │
│  今日 / 计划 / 时间表 / 项目 / 标签 / 笔记 / 通知 / Agent  │
│  命令面板 · 审批面板 · 斜杠命令                            │
└──────────────────────────┬───────────────────────────────┘
                           │ IPC
┌──────────────────────────▼───────────────────────────────┐
│ 宿主 Host（Tauri 主进程 + 领域服务）                        │
│  · SQLite 领域层（任务不变量、今日成员、重复实例）           │
│  · 提醒调度器 + 系统通知                                   │
│  · Provider Registry / 凭据                               │
│  · 插件装载 · MCP 进程池                                   │
│  · 工具执行与审批门                                        │
│  · 拉起 / 重启 Agent 子进程                                │
└───────────────┬───────────────────────────┬──────────────┘
                │ stdio / IPC 协议           │ 本机调用
┌───────────────▼──────────────┐   ┌────────▼──────────────┐
│ Agent Runtime（子进程）       │   │ workbench.db           │
│  回合循环 · 工具选择          │   │ notifications · FTS5   │
│  模型适配（按 Registry）      │   └───────────────────────┘
│  技能 / 子 Agent 编排         │
│  不持有 API Key               │
└──────────────────────────────┘

模型请求前：Agent → Host 索取 runtime headers（按 model_ref）
工具调用：Agent → Host 执行 ToolRegistry 中的实现
```

界面与 Agent **共用同一套领域函数**。界面按钮直接调 Host；Agent 工具是这些函数的契约包装。禁止 Agent 直连 SQLite。

提醒调度器属于 Host，应用托盘驻留时继续运行。Agent 崩溃或未启动不影响提醒。

### 9.1 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 | Windows 使用系统 WebView2；安装包和空闲内存小于 Electron；利于「轻 + 快」 |
| 界面 | React + TypeScript | 六大能力 UI 集中；配合虚拟列表与细粒度订阅 |
| 样式 | `@wb/theme` 设计令牌（CSS 变量）+ 组件 CSS | 统一浅/深色主题；避免运行时 CSS-in-JS；密度与强调色单一 |
| 动效 | CSS transform / opacity；必要时 `waapi` | 合成层动画，避开布局抖动 |
| 列表 | 虚拟滚动（今日、项目、知识树、通知、Agent 消息） | 千级条目仍保持滚动流畅 |
| 图标 | lucide | 线框、一种尺寸，SVG 可树摇 |
| 状态 | 轻量 store + 按查询键订阅 | 权威在 SQLite；界面只订所需切片 |
| 数据库 | 单个 SQLite，WAL，关键索引 + FTS5 | 本地读写路径最短 |
| Agent 运行时 | 独立子进程（sidecar） | 模型与工具不堵 UI |
| 模型适配 | Anthropic Messages / OpenAI Chat Completions / OpenAI Responses / Ollama | Provider 是数据 |
| 插件 | 本地目录 + 清单 | 技能、命令、子 Agent、钩子、MCP |
| 笔记编辑 | 第 2 阶段 CodeMirror 6 Markdown | 按需加载编辑器 chunk |

数据文件默认放在系统应用数据目录下的 `workbench/`。设置里可以改到**其它本地路径**（外置盘、用户文档夹等），并提供「在资源管理器中打开」和「复制备份到…」。不允许配置「云 API 作为库存储」。卸载应用时，文档中说明数据目录位置，避免用户误以为数据在云端。

### 9.2 视觉设计语言

目标：长时间使用不累、信息密度高但不挤，看起来像精心做的产品，而不是原型壳。

| 令牌 | 约定 |
| --- | --- |
| 色彩 | 跟随系统浅 / 深色；**一种**强调色用于当前导航、主按钮、计时中、未读；成功 / 警告 / 危险仅用于状态 |
| 字体 | 界面 UI 用系统字体栈（Segoe UI Variable 优先）；知识库正文可另选阅读字体，不污染列表 |
| 字号 | 12 / 13 / 14 / 20；列表主体 13–14；侧栏标签 12 |
| 间距 | 4 的倍数：8 / 12 / 16 / 24；侧栏宽 220；今日右侧时间表 320 |
| 行高 | 任务行约 32–36px，保证点击热区与一屏条数 |
| 圆角 | 控件 6–8px；面板 10–12px；不做大圆角胶囊堆 |
| 分割 | 1px 弱分割线；少用投影。需要浮层时用一层轻阴影或描边，禁止多层叠影 |
| 图标 | 16px 线框；提醒铃铛、计时、重复用同一套视觉权重 |
| 空状态 | 一句可执行文案 + 可选快捷键提示；不放插画充数 |

按能力微调，仍共用令牌：

- **任务 / 今日**：紧凑列表，完成态立刻划线或淡出；进行中一条用强调色左边线。
- **日程**：计划用等宽日期列；时间表用清晰小时网格，当前时刻一条细线；拖拽预览半透明块，不重绘整页。
- **知识库**：稍增正文字距与行高；编辑区与预览切换无整页闪白。
- **Agent**：消息气泡克制，工具调用折叠为一行摘要；流式输出不因每个 token 重排侧栏。
- **提醒 / 通知**：顶栏铃铛显示未读数；到期弹层居中偏上，动作按钮固定，不挡命令面板输入。

禁止项（与性能冲突或破坏扫读）：大面积毛玻璃、循环装饰动画、每行复杂渐变、仪表盘式多色统计卡墙、首屏自动播放。

### 9.3 性能预算与验收

在参考机器（近年 Windows 笔记本、集显即可）上，开发与发布构建均需可测：

| 指标 | 目标 |
| --- | --- |
| 冷启动到可交互今日 | ≤ 1.5s（含打开本地库；不含拉起模型） |
| 侧栏切换任务 / 日程 / 知识库 / Agent / 通知 | ≤ 100ms 首帧有内容（可先骨架再补齐） |
| 命令面板打开 | ≤ 80ms |
| 今日 / 项目列表滚动 | 滚动中尽量 60fps；千条任务不卡死 |
| 完成任务、改计划日 | 乐观 UI ≤ 50ms；落库失败可回滚并提示 |
| 提醒弹层出现 | 到期后 ≤ 1s（调度粒度允许分钟级扫描时，边界时刻可提前 1 个 tick） |
| 空闲内存（无 Agent 会话） | 明显低于同功能 Electron 实现；作为回归对比项记录 |
| Agent 流式输出 | 不阻塞列表滚动与计时秒表 |

实现要点：

1. 路由级与编辑器级 **code splitting**；首屏不加载 CodeMirror、图表、MCP 调试 UI。
2. 列表 **虚拟化**；知识树大数据量时按展开节点懒加载。
3. SQLite 查询带齐计划日、项目、提醒相关索引；避免在 Renderer 里全表过滤。
4. 界面订阅粒度到「当前视图查询结果」，禁止「任何写都重渲整棵树」。
5. 图片与附件（若后续有）缩略图异步；默认路径不解码大图。
6. 性能回归：关键路径留一个可脚本触发的测量清单，发版前跑一遍。

## 10. Agent（对齐 ZCode）

Agent 不是外挂聊天窗，而是工作台的操作面。实现上对齐 ZCode 的这些决定，用本应用自己的协议与表结构落地。

### 10.1 宿主与运行时

| 角色 | 职责 |
| --- | --- |
| Host | 窗口、SQLite、提醒调度、凭据、Provider Registry、插件与 MCP 生命周期、工具真正执行、审批 UI |
| Agent Runtime | 会话回合、拼上下文、选工具、流式输出、子 Agent；每次模型请求前向 Host 要 runtime headers |
| Renderer | 只经 IPC 调 Host；展示会话事件、审批卡片、工具结果 |

Agent 进程不持久化 API Key。无 Host 时无法对外部模型鉴权。这与 ZCode「凭据在桌面宿主、Agent 按次索取请求头」一致。

### 10.2 Provider Registry

`config.json` 里的 Provider 是数据，不是代码分支：

```json
{
  "providers": [
    {
      "id": "openai-compatible:local",
      "name": "Ollama",
      "kind": "openai-chat-completions",
      "baseURL": "http://127.0.0.1:11434/v1",
      "apiKeyRequired": false,
      "enabled": true,
      "models": { "llama3.1": { "limit": { "context": 8192, "output": 2048 } } }
    },
    {
      "id": "custom:acme",
      "name": "Acme",
      "kind": "anthropic-messages",
      "baseURL": "https://api.example.com",
      "apiKeyRequired": true,
      "enabled": true,
      "models": { "fast": { "limit": { "context": 128000, "output": 8192 } } }
    }
  ],
  "defaultModelRef": "custom:acme/fast"
}
```

`model_ref` 形如 `providerId/modelId`。会话可覆盖默认模型。内置示例可包含常见网关；用户可增删改。官方套餐若以后接入，仍走同一 Registry。

### 10.3 工具注册表（覆盖全部应用能力）

工具进入同一张 `ToolRegistry`，再按会话权限过滤后发给模型。内置工具按领域分组；插件 MCP 工具以命名空间加入，例如 `mcp__mail__send`。

**任务与计划**

| 工具 | 副作用 | 说明 |
| --- | --- | --- |
| `task_list_today` | 无 | 今日成员与顺序 |
| `task_list` | 无 | 按项目 / 标签 / 计划区间筛选 |
| `task_get` | 无 | 单条任务含提醒与子任务 |
| `task_create` | 写 | 建任务；遵守计划日 / 时刻互斥 |
| `task_update` | 写 | 改标题、笔记、项目、标签、预计时长 |
| `task_complete` / `task_reopen` | 写 | 完成时清提醒 |
| `task_schedule` | 写 | 设 `due_day` 或 `due_with_time`，可选提醒偏移 |
| `task_move_backlog` | 写 | 进待办清单并清空计划与提醒 |
| `task_set_deadline` | 写 | 截止日 / 时刻与截止提醒 |
| `task_set_reminder` | 写 | 只改提醒 |
| `task_add_subtask` | 写 | 子任务；不可设重复 |

**项目、标签、计时、日程**

| 工具 | 副作用 |
| --- | --- |
| `project_list` / `project_create` / `project_archive` | 读 / 写 / 写（破坏性） |
| `tag_list` / `tag_assign` | 读 / 写 |
| `timer_start` / `timer_stop` / `timer_status` | 写 / 写 / 读 |
| `event_list` / `event_create` / `event_update` | 读 / 写 |

**笔记与检索**

| 工具 | 副作用 |
| --- | --- |
| `note_get` / `note_search` / `note_create` / `note_update` | 读 / 读 / 写 / 写 |
| `link_mention` | 写 |
| `search` | 读，FTS |

**通知、视图、设置**

| 工具 | 副作用 |
| --- | --- |
| `notification_list` / `notification_snooze` / `notification_dismiss` | 读 / 写 |
| `ui_open` | 无，打开今日 / 计划 / 某任务 / 某笔记 / 通知中心 |
| `settings_get` / `settings_patch` | 读 / 写（不含密钥明文） |

**Agent 自身**

| 工具 | 副作用 |
| --- | --- |
| `session_set_model` | 无，改当前会话 `model_ref` |
| `plugin_list` | 读 |

所有写工具在 Host 执行前过领域不变量校验（互斥字段、子任务不能重复、禁止 `TODAY` 标签等）。校验失败以结构化错误返回模型，不落库。

### 10.4 权限与审批

对齐 ZCode「工具契约 + 审批」的思路，收束为本应用三档：

1. `readonly`：只注册读工具。
2. `confirm`：每个写工具弹出审批卡，展示工具名、自然语言摘要与参数差。
3. `session_auto`：本会话内对非破坏性写自动批准；破坏性写（删除、归档项目、批量清空）仍要确认。

审批卡与任务提醒弹层共用顶层区域，不互相覆盖：提醒优先保证可见，审批排队。

### 10.5 插件

插件目录形态对齐 ZCode，清单名改为 `.workbench-plugin/plugin.json`（兼容读取 `.zcode-plugin/plugin.json` 的同构字段，降低迁移成本，但不实现 ZCode 专有协议扩展）。

| 组件 | 作用 |
| --- | --- |
| Skill | 教 Agent 如何完成某类工作台流程的说明，注入可选上下文 |
| Command | `/` 斜杠命令，可带 `$ARGUMENTS` |
| Agent | 子 Agent 定义（名称、描述、system prompt、可用工具子集） |
| Hook | 在任务完成、提醒触发、会话开始等事件上跑自动化（第一版仅支持调用只读工具或投递通知） |
| MCP | stdio / HTTP 外部工具；进同一 ToolRegistry，默认需要审批 |

启用插件 = 注册其组件；停用 = 全部卸下。第一版只从本地文件夹安装，不做远程市场与自动更新。

### 10.6 会话上下文

线程可挂项目或全局。系统提示由 Host 组装，默认包含：

- 今日任务摘要（标题、计划、提醒、预计时长）
- 当前打开的任务或笔记（若有）
- 未读通知条数
- 已启用技能的短描述列表
- 当前 `model_ref` 与权限模式

不把整个库塞进上下文。需要细节时由模型调 `task_get` / `note_get` / `search`。

第 4 阶段的晨报是一次只读会话：读今日、时间表、收件箱未排期数量与到期提醒，生成文字，默认不调写工具。

## 11. 分阶段交付

### 阶段 1 · 任务 · 日程 · 提醒 · 通知

交付：收件箱项目与自建项目、进行列表和待办清单、今日（任务×日程时间线）、计划、时间表、标签、子任务、预计时长、按日计时、重复配置、计划 / 截止提醒、应用内通知中心、系统通知（托盘驻留时）、命令面板、快速输入、本地日程块、单文件备份；落实第 9.2–9.3 节的视觉令牌与性能预算基线。

验收：

- 无日期的新任务出现在收件箱项目，不出现在今日
- 设为今天的计划日后出现在今日；库里没有「今日」标签
- 再设具体时刻后，`due_day` 为空，任务离开计划列、出现在时间表
- 只设截止日的任务不进入今日，时间表上能看到截止标记
- 为有时刻的任务设「提前 15 分钟」后，`remind_at` 正确；到点出现应用内通知，可稍后提醒 / 打开 / 完成
- 忽略后约 5 分钟内不反复抢焦点；提醒记录仍在
- 应用最小化且托盘驻留时，系统通知可点回任务
- 子任务的计时汇总到父任务；完成任务后提醒被清除
- 每周固定重复在下一次打开时生成新实例；子任务不能设重复

此阶段没有知识库编辑器和模型。看板、艾森豪威尔矩阵留到任务主路径稳定之后。

### 阶段 2 · 知识库

交付：Markdown 笔记、笔记树、`mention` 反向链接、标题加正文的 trigram 搜索、从任务打开关联笔记；编辑器按需加载。任务短笔记保持原字段。

验收：笔记中的链接在对方页面出现；搜索中文子串能命中标题或正文；打开万字笔记不卡住今日视图的切换。

### 阶段 3 · Agent 与外部模型

交付：Host / Agent 子进程、Provider Registry、凭据按次下发、覆盖第 10.3 节的内置工具面、审批三档、项目 / 全局会话、流式输出、`ui_open` 与界面联动。

验收：

- 换一个 OpenAI 兼容端点与一个 Anthropic Messages 端点都能完成「列出今日 → 建任务 → 排到明天并设提醒」；密钥不出现在 Agent 日志
- 默认权限下写工具必须经审批才落库；拒绝后数据库不变
- `session_auto` 下建任务无需逐条点批准，但删除任务仍要确认
- Agent 创建的提醒会出现在通知调度里，与界面手动创建的行为一致
- Agent 崩溃后提醒仍触发；重启 Agent 可继续旧会话

### 阶段 4 · 插件、检索与晨报

交付：本地插件装载（技能、命令、子 Agent、钩子、MCP）、笔记分块与嵌入、晨报只读会话。

验收：启用插件后 `/` 命令与 MCP 工具可见；停用后消失。删除笔记后其片段不再被检索到；晨报默认不写库。

### 阶段 5 · 第二台设备（仍全部本地）

交付：可选的**用户自管**多设备同步（例如导出/导入库、指向用户自己的同步文件夹）。每一台设备上仍是完整本地副本；应用不托管云端库，不引入厂商账号。候选技术是同一 SQLite 上的变更日志。不接 Super Productivity 的 SuperSync 云服务。凭据默认不随库分发，需在每台设备本地配置。

## 12. 风险与约束

| 风险 | 处理 |
| --- | --- |
| 今日被做成标签或状态，和计划日各说各话 | 领域层禁止 `TODAY` 标签；今日查询只读计划字段 |
| 计划日和时刻同时有值 | 写入时清空另一列；读取时时刻优先 |
| 提醒在 Agent 里实现，导致未开会话就不响 | 提醒调度固定在 Host；验收包含「Agent 未启动仍提醒」 |
| 过期提醒反复抢焦点 | 应用内 5 分钟冷却；系统通知可合并 |
| 为美观引入重特效导致列表掉帧 | 第 5.0 / 9.2 禁止项；以 9.3 帧率指标卡发版 |
| 六大能力做成六个互不通的子 App | 共用领域层与令牌；Agent 工具面必须跨能力 |
| Agent 直写数据库绕过不变量 | 禁止 Agent 持有 DB 句柄；只经 ToolRegistry |
| 密钥进会话库或插件目录 | 凭据只在 Host；按次下发 runtime headers |
| 业务数据被静默上传或「顺便」进厂商云 | 无云账号；无上传库接口；外部模型仅当次请求；发版审查网络出口 |
| 插件 MCP 任意执行 | MCP 工具默认审批；第一版无远程市场 |
| 范围滑向议题同步、白板、电脑操控 | 以第 3 节为准 |
| 父任务和子任务的工时算重 | 有子任务的父任务显示汇总值，不接受直接计时 |
| WebView2 与以后其他系统的 WebView 不一致 | 第一版只承诺 Windows |
| 中文检索漏字 | FTS5 使用 trigram |
| 单文件损坏 | WAL；设置中复制备份 |

## 13. 参考

任务管理以 Super Productivity 为准：

- 计划日 `dueDay` 与时刻 `dueWithTime` 互斥，读取时时刻优先
- 「今日」是虚拟列表，成员由计划日计算，顺序单独保存，标签里永远没有 TODAY
- 计划视图只排到天；写了时刻就改由时间表显示
- 截止日独立于计划日；提醒可挂在计划时刻或截止时刻，常用提前偏移
- 收件箱是内置项目；项目内分进行列表和待办清单
- 工时按日本地日期累加，父任务汇总子任务
- 重复配置独立于任务；子任务不能重复

Agent、模型与插件以 ZCode 为准（思想对齐，协议自研）：

- 桌面宿主与 Agent 子进程分离；业务真相与凭据在宿主
- Provider Registry 描述外部模型；Agent 按次向宿主索取请求头
- 工具契约进入统一注册表；内置工具与 MCP 工具同一套权限与审批
- 插件打包技能、斜杠命令、子 Agent、钩子、MCP，启停一体
- 不把 Browser Use / Computer Use 与官方远程市场纳入第一版

其余部分：

- 命令面板：Linear 的 `Ctrl+K` 是主动作入口
- 双向链接与本地知识库：思源笔记。长文保持 Markdown
- 桌面壳与单 SQLite 文件：Tauri 2
- 本地优先 / 本机保存：Ink & Switch，*Local-first software*——本应用进一步收紧为「无云端业务库」
- 一个库文件同时放日志和投影：Epicenter ADR 0214，仅作为第 5 阶段用户自管同步的储备

许可与仓库现状以各项目当时的说明为准。

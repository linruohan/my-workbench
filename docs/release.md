# 发布标准

版本发布必须满足本清单。未勾选项不得对外宣称「正式版」。

## 1. 版本号

遵循语义化版本 `MAJOR.MINOR.PATCH`（当前从 `0.1.x` 起）：

| 变更 | 版本 |
| --- | --- |
| 不兼容的数据/API 变更 | MAJOR（1.0 前可用 0.x 表示不稳定） |
| 向后兼容功能 | MINOR |
| 向后兼容修复 | PATCH |

同步更新：

- 根目录 `package.json` `version`
- `apps/desktop/package.json` `version`
- `apps/desktop/src-tauri/tauri.conf.json` `version`
- `开发报告.md` 修订记录

## 2. 发布门禁（强制）

在干净工作区执行：

```bash
git status          # 应无未提交的发布相关改动遗漏
npm run check       # format:check + lint + typecheck + test
npm run pack:check  # 可选：再跑前端生产构建
npm run pack:win    # Windows 安装包 / 可执行文件
```

`npm run check` 任一失败 → **禁止发版**。

## 3. 功能验收（阶段相关）

### 3.1 阶段 1（当前最低）

- [ ] 无日期任务进收件箱，不进今日
- [ ] 排到今天后出现在今日；设具体时刻后离开计划列、进入时间表
- [ ] 提醒到期可出现应用内通知；稍后有冷却
- [ ] 主题可在「跟随系统 / 浅色 / 深色」间切换并本地持久化
- [ ] 断网下任务 / 日程 / 通知主路径可用
- [ ] 无云账号、无强制登录、无业务库上传逻辑

### 3.2 后续阶段

按 `docs/design.md` 对应阶段验收项追加，不得删减已有门禁。

## 4. 质量与安全

- [ ] 无密钥、Token、用户库进入 Git
- [ ] 依赖无明显高危漏洞（可用 `npm audit --omit=dev` 人工判断）
- [ ] 样式仅使用 `--wb-*` 令牌（抽查新增 CSS）
- [ ] 变更已写入 `开发报告.md` 修订记录或当次发布说明

## 5. 产物与分发

1. 产物路径见 `docs/packaging.md`
2. 对内测试可用未签名包；对外正式分发应使用代码签名（证书就绪后）
3. 发布说明需包含：版本号、主要变更、已知问题、数据迁移注意（若有）

## 6. 回滚

- 保留上一版本安装包至少一轮
- 数据库迁移必须向前兼容或提供导出；破坏性迁移需 MAJOR 并写明升级步骤

## 7. 发布记录模板

```markdown
## vX.Y.Z — YYYY-MM-DD

### 变更
- …

### 验收
- [x] npm run check
- [x] 阶段功能清单

### 产物
- 路径：…
- SHA256：（可选）
```

将当次记录追加到 `开发报告.md` 附录或 `docs/releases/`（若目录已创建）。
